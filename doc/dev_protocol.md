# 递归式 AI 协同开发协议 (Master Protocol v2.0)

**版本**: v2.0.0
**目标**: 通过文档驱动 (DDD)、对抗迭代与测试先行 (TDD) 机制，实现生产级代码交付。

---

## 核心准则：文档驱动开发 (DDD)
- **流水线流向**: `intent.md` (意图) -> `design.md` (对抗后方案) -> `implementation` (测试驱动实现)。
- **一致性原则**: 严禁代码逻辑偏离 `design.md`。若发现逻辑漏洞，必须先回溯修正 `design.md`，严禁“直接修代码”。
- **状态维护**: 所有开发任务必须实时更新 `@docs/project_status.json`。

---

## 阶段一：意图澄清与上下文注入
- **自动检查**: 检测 `./docs/intent.md` 是否存在，不存在则自动创建并填充模板。
- **上下文初始化**: 强制读取 `@docs/project_status.json`，加载历史进度、技术债与 API 合约。
- **任务**: 提出 3 个关键澄清问题，明确业务边界与非功能需求。
- **输出**: 初始化并填充 `intent.md`。

## 阶段二：文档驱动设计
- **自动检查**: 检测 `./docs/design.md` 是否存在，不存在则自动创建并填充模板。
- **任务**: 输出详细设计，包含：
    - Pydantic 数据模型与接口契约 (Contracts)。
    - 资源生命周期管理（初始化/释放）。
    - 核心逻辑流图与目录结构。

## 阶段三：对抗性迭代与 TDD 校验
- **流程**: 加载 `@docs/qa_agent.md` 进行 3 轮循环：
    - **QA (Red Team)**: 批判方案，并强制提供 **“失败测试用例 (Failing Test Case)”** (Pytest 格式)。
    - **Dev Agent**: 必须编写代码满足该测试用例，并在每一轮后更新 `design.md` 中的对抗结论。
- **质量门槛**: QA 裁决为 `[批准]` 后，方可进入编码。

## 阶段四：测试驱动编码
- **任务**: 基于阶段三通过的测试用例生成生产代码。
- **约束**: 禁止任何未覆盖测试的逻辑；强制类型提示 (Type Hinting)；严禁使用 `Any` 类型；严禁空 `except` 块。

## 阶段五：回归影响评估 (Regression Impact Analysis)
- **任务**: 强制输出 Checklist 并执行：
    - [ ] **依赖树分析**: 列出受影响模块及引用关系。
    - [ ] **场景关联**: 核心 API 路径、外部工具调用、下游解析器稳定性校验。
    - [ ] **集成测试**: 运行并展示集成测试结果。

## 阶段六：最终审计与持久化
- **审计 AI**: 对设计与代码进行 0-10 评分，输出待修复技术债务清单。
- **状态同步**: 自动更新 `@docs/project_status.json` 中的 `completed_tasks` 与 `known_risks`。

---

## 💡 交互范式与约束
1. **状态看板**: 每一轮对话的开头，必须输出看板：`[当前阶段: X] [已完成进度: Y]`。
2. **拒绝盲从**: 若 QA 发现严重风险，禁止编码，必须在 `design.md` 中完成修复闭环。
3. **拒绝重复**: 每一轮反馈必须基于上一轮，禁止循环重复建议。
4. **拒绝流于形式**: 若 AI 交付质量不达标，立即执行“回退指令”，强制重新进行阶段对抗。
