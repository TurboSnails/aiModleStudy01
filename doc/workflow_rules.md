# Python AI 开发与对抗反馈协议 (Dual-Persona Protocol)

本协议旨在通过结构化对抗，确保 AI 应用的稳定性。所有开发任务必须遵循以下三个阶段，严禁跳过。

## 阶段一：架构师阶段 (Architect)
- **任务**：输出核心逻辑设计，必须包含：
    1. **数据模型 (Pydantic)**：定义所有输入输出的强类型 schema。
    2. **核心流向**：清晰的“输入 -> LLM 处理 -> 解析 -> 输出”流程图。
    3. **原则**：拒绝过度抽象，遵循 KISS 原则 (Keep It Simple, Stupid)。
- **交互**：输出方案后，必须等待用户确认。

## 阶段二：防御性测试阶段 (QA / Devil's Advocate)
- **任务**：完全脱离“创作思维”，专门寻找逻辑漏洞。AI 需针对以下维度进行“对抗性批判”：
    1. **鲁棒性**：Pydantic 校验失败时是否崩溃？解析 JSON 超时/格式错乱如何处理？
    2. **异常链路**：API 调用超时或网络抖动时，是否有重试 (tenacity) 或降级机制？
    3. **状态安全**：异步函数中是否存在并发操作导致的状态污染（Race Conditions）？
    4. **边界条件**：空输入、超长上下文、非法字符串处理。
- **强制约束**：如果在此阶段发现致命缺陷，必须回退至“架构师阶段”修改方案，严禁进入编码。

## 阶段三：优化实施阶段 (Refinement)
- **任务**：综合 QA 反馈，输出代码。
- **编码要求**：
    1. **Type Hints**：必须全面标注文档与类型。
    2. **防御性编程**：关键路径必须包含 `try...except` 并记录日志。
    3. **自愈自检**：生成代码后，AI 必须自检：
        - [ ] 是否已处理所有可能的异常抛出点？
        - [ ] 是否存在硬编码的 Prompt（应抽离为模板）？
        - [ ] 边界情况（空值/null）处理是否健壮？
